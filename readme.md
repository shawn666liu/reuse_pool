# Reuse Pool

`document generated by DeepSeek:`  

一个高性能、线程安全的 Rust 对象池库，专注于零拷贝内存复用和自动归还。
特别适用于高频数据流场景（如每秒数千个 Tick 数据的处理），可大幅减少堆内存分配和释放的开销。

## 核心特性

- **零拷贝**：所有对象在堆上只分配一次，后续仅传递指针，无数据复制。
- **线程安全**：基于 `Arc` 和原子操作，支持跨线程共享与自动归还。
- **类型安全**：通过 `PooledMut` 和 `Pooled` 分离可变填充阶段与只读共享阶段，防止误用。
- **灵活的容量控制**：支持有界（`ArrayQueue`）和无界（`SegQueue`）两种队列，满足不同内存约束。
- **可定制创建**：可通过工厂函数自定义对象的创建方式，不强制要求 `Default` 实现。
- **自动归还**：最后一个 `Pooled` 引用销毁时，对象自动返回池中，无需手动操作。

## 设计思路

对象池内部维护一个并发队列（默认使用 `SegQueue`）来存放空闲的 `Box<T>`。
当用户需要对象时：
1. 调用 `pool.get()` 获取一个 `PooledMut<T>`（可变守卫）。
2. 通过 `DerefMut` 或 `as_mut()` 填充数据。
3. 填充完成后调用 `freeze()` 转换为 `Pooled<T>`（只读共享智能指针）。
4. `Pooled<T>` 可被克隆并分发到多个消费者，内部使用 `Arc` 管理引用计数。
5. 当最后一个 `Pooled<T>` 销毁时，对象自动归还给池，等待下一次复用。

整个过程中，`T` 的数据始终位于堆上同一地址，仅指针在不同所有者间移动，实现了真正的零拷贝。

## 快速开始

```rust
use reuse_pool::{Pool, Reset};

// 假设您的数据类型实现了 Default（也可以使用自定义工厂）
#[derive(Debug, Default)]
struct TickData {
    symbol: String,
    price: f64,
    volume: u64,
}

// 创建无界对象池
let pool = Pool::<TickData>::new_unbounded();

// 获取可变守卫并填充数据
let mut guard = pool.get();
guard.symbol = "BTCUSD".to_string();
guard.price = 50000.0;
guard.volume = 100;

// 冻结为共享只读对象
let tick = guard.freeze();

// 分发克隆给多个消费者
let tick_for_bar = tick.clone();
let tick_for_db = tick.clone();

// 使用后自动归还
drop(tick_for_bar);
drop(tick_for_db);
drop(tick); // 最后一个引用触发归还
```

## 核心类型

- [`Pool<T, Q>`]：对象池，管理空闲对象和创建逻辑。
- [`PooledMut<T, Q>`]：可变守卫，独占访问，用于填充数据。
- [`Pooled<T, Q>`]：共享只读智能指针，可克隆，自动归还。
- [`Queue<T>`]：并发队列 trait，支持 `ArrayQueue`（有界）和 `SegQueue`（无界）。

## 容量控制

- **无界池**：使用 `new_unbounded()` 创建，所有归还对象都会被缓存，永不丢弃。适合内存充足、对象创建成本高的场景。
- **有界池**：使用 `new_bounded(max_idle)` 创建，最多缓存 `max_idle` 个空闲对象，超过上限的新归还对象将被丢弃（内存立即释放）。适合内存敏感的场景。

您可以通过 `pool.status()` 获取当前空闲数、最大空闲限制和累计创建数，用于监控和调优。

## 自定义对象创建

如果您的类型没有实现 `Default`，可以通过 `with_factory` 或 `get_with` 传入工厂函数：

```rust
# use reuse_pool::Pool;
struct MyType { data: Vec<u8> }

// 使用 with_factory 创建池
let pool = Pool::<MyType>::with_factory(
    crossbeam::queue::SegQueue::new(),
    None,
    || MyType { data: Vec::with_capacity(1024) }
);

// 或者在 get 时临时指定工厂
let guard = pool.get_with(|| MyType { data: Vec::with_capacity(1024) });
```

## 跨线程使用

对象池本身是 `Sync + Send`，可在多线程间共享。`Pooled<T>` 也是 `Send + Sync`，可安全地跨线程传递：

```rust
# use reuse_pool::Pool;
# use std::thread;
# #[derive(Default)] struct TickData;
let pool = Pool::<TickData>::new_unbounded();
let tick = pool.get().freeze();

let handle = thread::spawn(move || {
    // 在另一个线程中使用 tick
    drop(tick);
});
handle.join().unwrap();
// 对象自动归还到原池
```

## 注意事项

- 调用 `get()` 获取 `PooledMut` 后，必须确保在 `freeze()` 之前填充好数据，因为之后将无法修改。
- 如果 `PooledMut` 在没有调用 `freeze()` 的情况下被丢弃，对象会自动归还（但此时数据可能未初始化，下次获取时应重新填充）。
- 对于大型结构体，建议将数据放在堆上（如使用 `Vec`、`Box`），以减少 `Pooled` 本身移动时的栈复制开销。
- 有界池的 `max_idle` 应设置为系统并发峰值时可能同时存在的空闲对象数，通常远小于总创建数。过小会导致频繁创建新对象，过大则浪费内存。

## 性能提示

- 默认无界池使用 `SegQueue`，是无锁的高性能队列，适合大多数场景。
- 如果明确需要上限且队列满时丢弃旧对象，可使用 `ArrayQueue` 的有界池。
- 内部使用 `Relaxed` 原子序数，在 x86 等强内存模型下已足够，若需更强的顺序保证可调整。
